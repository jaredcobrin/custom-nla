# Curriculum plan: no SFT, pure RL+LoRA, scaffolded bootstrap

This supersedes the "AR warm-start on C4 text → activation pairs" idea at the
bottom of `CLAUDE.md` — that idea has the same underlying flaw as Anthropic's
own SFT approach (see "The core epistemic problem" below), just discovered
through a different path. This file is the revised plan.

## The goal, restated

Do what Anthropic's NLA paper does — AV explains an injected activation, AR
reconstructs the activation from the explanation, trained via RL — but
**without any SFT warm-start stage**, and **without any externally-generated
labels** (no Claude-guessed "thoughts"). Training is pure RL, LoRA on both AV
and AR, matching this project's existing architecture
(`av_model.py`/`ar.py`/`training.py` — Qwen2.5-1.5B + LoRA, `<OVERHERE>`
injection token, stripped lm_head/final-norm + value head on AR).

## Why not just do what the paper does

The paper's SFT stage pairs (activation, Claude Opus 4.5's guess at "what the
model would be thinking to predict the next token") — verified from the
actual prompt used
(`nla/datagen/stage2_api_explain.py` in the paper-improvement fork):
Claude never sees the activation, only the source text. So the label is a
plausible guess derived from reading text, not a verified readout of what
the vector encodes. This bias then gets **permanently preserved** — RL's
objective in the paper includes a KL penalty anchoring the policy back to
the SFT-initialized model (`β · D_KL(AV_φ ‖ AV_φ_init)`), so whatever
text-reading habit SFT installs never has to loosen.

This project's own already-tried fix (AR warm-start on C4 text → activation
pairs, in `CLAUDE.md`) has the same structural problem, discovered
independently: training AR on **real source text** paired with the vector
still teaches "map text to vector," not "map a description of what's
represented in the vector to the vector" — and AR would never see raw
source text again after warm-start (it only ever sees AV's *generated
explanations* at actual use time), so it's also a train/test mismatch on top
of the epistemic issue.

## The core epistemic problem (why this is hard, not solvable by "removing bias")

Even this plan's own bootstrap phase (below) doesn't escape this cleanly —
worth being honest about that up front, not just once. During the
heavily-scaffolded early phase, AV's explanations are generated by reading
the visible prompt text, same underlying source of information as Claude's
guesses were. **The difference isn't that this plan's starting point is
unbiased — it's that nothing anchors the model to that starting bias
permanently.** There's no KL penalty here holding AV to its early,
text-reading habits. The curriculum (below) is specifically designed to make
that habit *stop working* over time, forcing genuine reliance on the vector
to emerge — that's the actual bet this plan is making, not "we avoided the
bias entirely."

## Architecture (unchanged from current project)

- Base model (frozen): Qwen2.5-1.5B, source of activations.
- AV: Qwen2.5-1.5B + LoRA, injects the activation at `<OVERHERE>`.
- AR: Qwen2.5-1.5B + LoRA, lm_head + final norm stripped, linear value head.
- Corpus: `HuggingFaceFW/fineweb` (`sample-10BT` config) — matches the actual
  NLA paper's reproducible datagen config
  (`configs/datagen/qwen7b_fineweb_1M.yaml` in `kitft/natural_language_autoencoders`).
  The paper's released checkpoints used a private Ultra-FineWeb slice that's
  no longer hosted; the repo itself recommends the plain FineWeb sample for
  fresh reproductions. Replaces the project's prior `allenai/c4` source —
  same streaming/shuffling mechanics, just a different `datasets.load_dataset`
  call, since both expose a `text` column.

## A rejected alternative, for the record

Considered replacing the single-AV-model visible-fraction curriculum below
with two separate AV models — one conditioned only on the visible text, one
conditioned only on the activation — blended per-token (weighted mixture of
their next-token distributions, shifting weight toward the activation model
over training). Rejected: mixing in a second model that has genuine access
to real information (the source text) gives the activation model somewhere
to hide. It can get reinforced for generic, activation-independent filler
that free-rides on the text model's real contribution to a good shared
reward, without ever being forced to learn genuine activation-dependence —
a new, easier path into the same generic-collapse failure mode described
below, that doesn't exist when there's only one author. The single-model
curriculum (vary what's visible to one model, not which model is talking)
doesn't have this failure mode: if the one model goes generic, it fails
self-evidently across every activation it's tried against, since there's no
co-author propping up the reward.

## The curriculum

### AV prompt structure

One fixed template, with the *amount* of visible source text varying, never
the template's shape (switching between "prompt with text" and "prompt
without text" as different-looking structures risks confounding "less
information" with "the input suddenly looks unfamiliar" — keep the shape
constant, vary only the content of one slot):

```
Context (may be partial or unavailable): {source_text_prefix_or_empty}
<OVERHERE>
Describe what this activation represents.
```

State explicitly in the instructions that the activation is the reliable
channel and the context may be incomplete — sets the incentive framing from
the first training example, not just once the crutch is gone.

### What varies, and how much

Collapse "is text shown at all" and "how much is shown" into one knob:
**what fraction of the source text, up to the point the activation was
extracted from, is visible.** 1.0 = full prefix visible. 0.0 = nothing.

- **At 1.0** (full prefix visible): AV's task reduces to "describe the text
  you can see" — something the base instruct model can already do
  reasonably well, so early rollouts are coherent from step one, giving AR
  (see below) real signal to learn from immediately. This is what breaks the
  original bootstrapping deadlock (`CLAUDE.md`'s "AR needs good AV
  explanations, AV needs good AR reconstruction" circularity) — via a
  different mechanism (an easy version of the task) than the paper's SFT
  warm-start uses (external labels), but solving the same problem.
- **As the fraction decreases**: even when *some* context is shown, it's an
  incomplete prefix — cut off before the point the activation was actually
  extracted from. This means the visible text literally cannot answer the
  full task on its own; some content is only recoverable from the
  activation. (This is "information insufficiency" — distinct from and
  complementary to dropout, see below.)
- **Randomized, not fixed, truncation point**: don't always cut at the same
  relative position — vary it — so AV can't learn a shortcut specific to one
  particular truncation amount.

### The schedule is performance-gated, not step-count-based

Do not decrease the visible fraction on a fixed clock (e.g. "step 500 → cut
50%"). Instead: track a rolling measure of AR's reconstruction quality
(FVE, fraction of variance explained) and only decrease the fraction once
it crosses a threshold. Expect FVE to *drop* after each decrease (less
information available) — hold at the new, smaller fraction until FVE
recovers back past the threshold, then decrease again. Repeat until the
fraction reaches 0.

**Gate on a held-out zero-context probe, not on in-curriculum FVE.**
Measuring FVE at the training-time visible-fraction level doesn't
distinguish "AV genuinely learned to use the activation" from "AV got
better at copying or paraphrasing whatever text is currently visible" — at
high fractions, the latter is a cheap way to inflate reconstruction quality
without any real grounding in the activation. A verbatim-overlap check
doesn't fix this either, since paraphrasing sidesteps it without adding any
real grounding. If the schedule advances on a shortcut-inflated signal, the
model can race through the easy levels having banked no real
activation-reading skill, then hit a level where copying stops working and
crash into the exact bootstrapping deadlock the curriculum exists to avoid
— just relocated one or two levels in instead of at step 0.

Fix: decouple what's *trained on* from what's used to *judge readiness*.
Keep training on the current curriculum level (that's what gives coherent,
learnable rollouts). But every `EVAL_INTERVAL` steps, run a separate,
held-out eval batch with the visible fraction forced to exactly 0 —
no text at all, only the activation — regardless of where training
currently sits on the ladder. Compute FVE only on that batch. Because
there's nothing to copy or paraphrase in that condition, that number can't
be gamed the way in-curriculum FVE can. Use a rolling window of these
zero-context probe values, with hysteresis (require the window's average to
sit above threshold for `min_hold_steps`, not just touch it once), as the
actual gate for curriculum advancement — and as the honest headline
progress metric, not the in-curriculum FVE. Cross-activation/entropy
diagnostics (below) remain useful as a secondary check for a different
failure signature (boilerplate collapse) than this probe catches (text
reliance vs. activation reliance).

This is a "level up when ready" curriculum (sometimes called self-paced /
adaptive curriculum), as opposed to a blind schedule — more robust because
it never advances difficulty faster than the model has actually
demonstrated it can handle, at the cost of needing to track a metric and
pick threshold values (tune empirically — no principled way to derive
these numbers in advance).

Named prior art for the general technique (dropout of an easy/privileged
signal to force reliance on a harder one, without the model permanently
learning to ignore the harder signal): **Learning Using Privileged
Information (LUPI)**, and its RL-specific instantiation, **Privileged
Information Dropout in RL**. Modality dropout in multimodal learning is the
closest concrete precedent for "one modality dominates, dropout forces
reliance on the other too" — e.g. a talking-face generation model that
learned to ignore audio in favor of video until modality dropout forced it
to use both. As of this writing, no prior work combines this specifically
with activation-verbalizer / NLA-style training — this is genuinely
untested territory, not a known-working recipe. Confirm this stays true
closer to any write-up; the space moves fast.

### AR training

Train AR **simultaneously with AV, on AV's own generated outputs** — not on
Claude-style guessed labels, not on real source text. No separate bootstrap
phase for AR at all. This works specifically *because* of the scaffold: AV's
early outputs, produced while heavily scaffolded, are already reasonably
coherent (leaning on the base model's pre-existing text-description skill),
so AR gets decent-quality, actually-representative training data (AV's own
explanation-style text, the only kind it will ever have to process) from
the very first step — no train/test mismatch, no separate warm-start needed.

**Known, real risk, not hypothetical**: fully joint training of two
co-adapting networks, neither with an independent stable starting point, is
closer to GAN-style training dynamics than the paper's staged approach
(separate SFT for both, then joint RL) — can be genuinely less stable.
Watch for: loss oscillating rather than trending down, or AR quality
tracking AV quality with enough lag to cause overshoot. This is a real
trade — avoiding the train/test mismatch of pretraining AR on real text
costs the stabilizer that separate warm-starts would have provided.

## A concrete, already-observed risk this plan needs to actively guard against

`CLAUDE.md`'s existing training log already recorded a real reward-hacking
episode (steps ~260-280): AV discovered that **echoing the av_prompt's own
wording** scored well on the semantic-meaning scorer, and this got
reinforced across the GRPO group before recovering. This happened *without*
the prompt scaffold this plan introduces. Deliberately showing AV the
source prompt text makes this exact, already-observed failure mode more
available, not less — echoing visible context text is now a much shorter,
easier shortcut to a good-looking reward than it was before. This is the
concrete, specific version of the general "scaffold becomes a permanent
crutch" risk discussed above — watch for it explicitly (e.g., check whether
AV's explanations contain verbatim spans from the visible context beyond
what's needed) rather than only monitoring aggregate reward/FVE curves.

## Collapse/health diagnostics to keep (from existing `CLAUDE.md`, still apply)

- GRPO_std should stay meaningfully above ~1e-8 (else AR is outputting the
  same vector regardless of input).
- AV gradient norms in a stable range (roughly 1-50 per existing notes;
  well below suggests barely learning, well above suggests instability).
- Cross-test: explanation of activation A scored against activation B
  should be low.
- Entropy across explanations: different activations should visibly produce
  different text, not generic boilerplate.
- New, specific to this plan: FVE-vs-visible-fraction curve — the shape of
  the recovery after each fraction decrease is itself a diagnostic. A
  recovery that gets slower/shallower each time the fraction drops suggests
  the model is running out of genuine vector-reliance to fall back on, not
  just needing more steps.
